# 投稿审核规则

## 流程与责任

投稿 → 完整性检查 → 来源及隐私检查 → 内容抽检 → 修改反馈 → 合并或关闭。

维护者负责最终合并。普通投稿至少由一名非投稿者维护者审核；涉及试题、答案或授权争议时，尽量由两名维护者复核。项目初期只有一名维护者时，应在 PR 记录该情况及核验过程；依据不足时暂缓收录，不以人员不足替代审核。

不承诺固定响应期限。资料不因临近考试而跳过审核，维护者也不对内容准确性作保证。

## 审核清单

| 维度 | 通过条件 | 未满足时 |
| --- | --- | --- |
| 信息完整 | 课程、学年、文件用途和修订说明齐全 | 要求补充 |
| 来源与权限 | 作者及具体来源明确，公开托管和协作有依据 | 暂缓，无法补足则拒绝 |
| 隐私 | 正文、截图、文件属性、批注中无不必要个人信息或凭据 | 要求脱敏；敏感文件及时移除 |
| 考核边界 | 无未公开试卷、进行中考试内容、违规获取答案 | 拒绝并移除违规内容 |
| 文件可用性 | 可打开，命名目录规范，无明显恶意内容 | 要求修正或拒绝 |
| 内容质量 | 范围清楚，抽检未见严重错误，题目性质准确标注 | 要求纠错或注明局限 |
| 索引维护 | 课程 README、授权和根课程索引同步 | 要求补齐 |

笔记抽检至少查看开头、中间与末尾；含公式和解析时核对代表性推导，并在 PR 记录查看范围。抽检不能证明全部内容正确。外部链接需核对发布者和可访问性，不能仅因可下载就认定允许镜像。

## 决策与记录

- 通过：清单符合要求，在 PR 记录审核范围、权限依据摘要和遗留限制后合并。
- 待补充：在 PR 列出具体问题，投稿者补充后重新检查相关部分。
- 拒绝：说明所依据的规则；来源无法核验、未经许可转载、泄题、隐私问题未解决等不得合并。
- 重复：链接到现有资料；确有更正或版本差异时引导为更新投稿。

建议创建标签：`submission`、`correction`、`request`、`rights`、`needs-info`、`approved`。标签需在仓库 Settings / Issues 相关界面或 Issues → Labels 手动创建，不会因模板文件自动出现。

## 合并方式与复查

建议 Squash merge，并保留投稿者署名与 PR 讨论记录。合并前确认审核针对最新提交；新增文件或变更权限说明后需要重新审核对应部分。维护者自己的内容也应记录自检与权限说明，有其他维护者时由其复核。

上线后收到严重错误、侵权或隐私反馈，应先控制影响，再核验。对不适宜公开的文件可先移除，决定与理由留最少必要记录，不复述敏感内容。投稿者可在原 PR 说明异议并补充依据，由另一名维护者复核；只有一人维护时公开说明这一限制。
